# Environment Variable Diff (ENVDIF) - process application

Environment variable values of two snapshots side by side - the same container on two snapshots, two containers, or the same snapshot on another server reached with its own base URL and technical user - marked MISSING in A / MISSING in B / DIFFERENT / same, with CSV; a Snapshots tab lists the containers and versions of the server.

Package `Environment-Variable-Diff-1.0.twx` (generated by `tools/build_envdif.py` on twxkit + kitlib, standard library only, no base export); targets: BAW 20.0.0.1+ (the lab reports `8.6.2.20001`), 24-26 traditional and CP4BA (/ops API); not the original 8.6.2.
Vanilla BAW: UI Toolkit controls only, one client-side human service, server-side service flows calling the REST API with the technical
user of the environment variables. Import through the Process Center / Workflow Center console (`pc_import.py`) or Studio, set the
environment variables of the snapshot, open the dashboard from Process Portal or the playback URL of the `.ids.json`.

## Dashboard

| Tab | Content |
|---|---|
| Compare | A: container + snapshot; B: container + snapshot (empty = A), other server URL + user + password (empty = this server); All variables / Differences only; Compare; Export CSV |
| Snapshots | container filter, List snapshots |

Every list has a status line; errors open a message modal; CSV export shows the text in a modal for copy / paste.

## Service flows and REST calls

| Flow | Does |
|---|---|
| EV Init | header |
| EV Snapshots | `GET /ops/std/bpm/containers?type=PA`, `GET /ops/std/bpm/containers/{acr}/versions` |
| EV Diff | `GET /ops/std/bpm/containers/{acr}/versions/{v}/env_vars` (pairs name / value) for A and B; for another server the flow logs in there itself (`POST <url>/bpm/system/login` with basic auth of the given user -> `csrf_token`, then `BPMCSRFToken` on the env_vars call) |
| EV Rows To CSV | rows -> CSV |

## Environment variables

`serverBaseURL`, `restAuthUser`, `restAuthPassword`, `restTrustAllCertificates` (kit-rest.js: the technical user every server-side flow calls the REST API with), `appTitle`, `opsLoginPath` (default `/bpm/system/login`, CP4BA `/bas/bpm/system/login`), `opsBasePath` (default `/ops/std/bpm`, CP4BA `/bas/ops/std/bpm`).

## Business objects

EVListQuery, EVSnap, EVList, EVQuery (containerA, versionA, containerB, versionB, otherServerUrl, otherUser, otherPassword, hideSame), EVRow, EVResult, EVCsv.

## Build, test, verify

```
python3 tools/build_envdif.py --snapshot 1.0                       # -> Environment-Variable-Diff-1.0.twx + .ids.json
KITENV_serverBaseURL=https://<host>:9443 KITENV_restAuthUser=<user> KITENV_restAuthPassword=<pw> \
  python3 tools/build_envdif.py --snapshot 1.0-lab                 # lab build with real defaults (a snapshot caches tw.env: new name)
python3 tools/pc_import.py Environment-Variable-Diff-1.0-lab.twx
python3 tools/kit_flow_test.py Environment-Variable-Diff-1.0-lab.ids.json "<flow>" '{"data": {...}}'   # every flow over REST
python3 tools/dash_test.py <host> <branch> <cshs>             # playback: tabs, JS errors, failed calls
```

Verified: BAW 26 lab: snapshots listed; HDLS 1.0 compared with itself (3 same) and with the same snapshot on the 8.6.2.20001 lab through the other-server path (its own CSRF login; 3 same); an unknown container answers CWTBG0624E and is reported. Dashboard playback: no JavaScript error, no failed call.

## Pitfalls met

* Every `/ops` call needs the `BPMCSRFToken` header from `POST /bpm/system/login` (`{"refresh_groups": true, "requested_lifetime": 7200}` with basic auth); without it: CWTBG0651E. `kitOps` in kit-common.js logs in once per script run.
* `/ops` exists from 20.0.0.1 on (verified: the other-server comparison against the 8.6.2.20001 lab answered); the original 8.6.2 has none.
